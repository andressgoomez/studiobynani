purpose: Build substrate para una aplicación local React + Node con migración web futura
altitude: initiative
updated: 2026-09-22T22:21

- (decision) Paradigma: modular monolith con frontend React y API Node en el mismo repositorio; evita complejidad distribuida y permite despliegue web futuro.
- (decision) Ejecución inicial: servicio Node local en la notebook y frontend servido por el mismo proceso; acceso por navegador en localhost.
- (decision) Base de datos inicial: SQLite como archivo local portable; la capa de persistencia debe aislar el motor para permitir migración futura a PostgreSQL.
- (decision) Frontend: React 19.3 con Vite 8.3 y TypeScript; backend: Node.js 24.20 LTS con Fastify 5.12.5.
- (decision) ORM y migraciones: Prisma 7.10 estable con SQLite; evitar Prisma 8 RC en producción.
- (decision) Los cálculos de precios, descuentos, comisiones y entregas a NANI pertenecen al dominio del servidor, no al frontend.
- (decision) La API es la única dueña de las mutaciones; React consume endpoints y no escribe directamente en SQLite.
- (decision) Autenticación local: selector de usuario + PIN corto; sesión administrada por Node y permisos aplicados en API.
- (decision) La fecha/hora de atención la genera el servidor usando zona horaria del estudio.
- (decision) Backup local periódico de SQLite es obligatorio antes de considerar una futura migración web.
- (decision) Se agrega un único servicio de liquidación como fuente canónica para precio final, comisión y entrega a NANI; canceladas y ausentes tienen importe y comisión cero.
- (decision) Se centraliza el tiempo: instantes UTC, zona IANA configurable con valor inicial America/Argentina/Buenos_Aires y businessDate único.
- (decision) Cerrar caja crea un snapshot; mutaciones posteriores del día cerrado se rechazan hasta que NANI reabra con motivo y auditoría.
- (decision) Cada entidad tiene un módulo dueño y los derivados financieros se guardan como snapshots con versión de cálculo.
- (decision) Los contratos API se versionan bajo /api/v1 con esquemas compartidos y mutaciones idempotentes cuando corresponda.
- (decision) El backup SQLite se ejecuta mediante mecanismo consistente al cerrar el día, rota copias y debe poder restaurarse en una verificación manual.
- (decision) Se usará npm workspaces y package-lock.json para reproducibilidad local.
